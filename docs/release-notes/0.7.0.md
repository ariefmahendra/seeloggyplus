# SeeLoggyPlus 0.7.0

## Overview
This release makes SeeLoggyPlus feel faster and clearer from the first second: an
animated splash covers startup, log tabs adapt to their count like a modern editor,
servers can be organized directly by dragging, and every error dialog now explains
what happened and what to do next — in plain language.

## Features
- **Animated startup splash**: logo, version and an animated progress bar with the
  current startup phase, shown before the app window appears — including hidden
  `javaw` launches from the Windows VBS shortcut. It closes as soon as the main
  window is ready, with no artificial waiting.
- **Adaptive log tabs**: tab headers shrink proportionally as you open more tabs and
  grow back when tabs close or the window widens. Names stay readable, long ones are
  ellipsised, and the full name stays available via tooltip and the tab overflow menu.
- **Server reordering in Locations**: drag a server between rows to reorder it inside
  a group or in the ungrouped list; the order is saved. Dropping onto a group folder
  moves the server into it, and dropping onto Local Drive or empty space removes it
  from its group.
- **Clear drop feedback**: a line above or below the row means "place here", while an
  area highlight means "join this group", with a small hint describing the action.
- **New group anywhere**: right-click the Locations panel — heading, empty space or
  favorites — to create a group at the top level.
- **Contact in About**: the maintainer email is shown as a clickable mail link that
  follows the active theme.

## Fixed
- **Clear Log View**: the toolbar Clear button now actually empties the active tab.
  It stops tailing, releases the session's file resources and buffers, clears the
  Detail panel and resets the status bar — while keeping the tab open, so Reload
  (Ctrl+R) or Tail restores the same file.
- **Remote files named `seeloggyplus-...`** (for example temporary-looking names in
  `/tmp`) are no longer rejected as local copies. They can be tailed and reopened
  from Recent normally.
- **Readable error dialogs**: a login rejection now says the server rejected the
  login and points to the username/password or the private key/passphrase,
  depending on the configured method. Timeouts, refused connections, unknown hosts,
  unreadable key files and a changed server identity each get their own explanation.
  The raw technical message stays available under **Details**.
- **Invalid or missing server locations** explain how to open File Manager and pick
  the original file, instead of showing a raw path and a misleading "Windows local
  path" message.
- File Manager returns to the local location immediately when a connection fails,
  without waiting for the error dialog to be closed.
- Toolbar toggle icons keep readable contrast while pressed in the Light theme.

## Improvements
- Tail button uses a terminal icon; Detail Clear and Close use distinct eraser/X
  icons instead of two identical X buttons.
- Buttons in the Detail panel, File Manager and Recent Log Files panel match the
  compact density of the main toolbar; "Clear Recent Files" no longer stretches
  across the whole panel.
- Recent Log Files group headers show only the server name, without a file count.
- Reopening a file (from Recent, a reused File Manager tab, or re-enabling Tail)
  updates its last-opened time and moves it to the top of its group while keeping
  the highlight. Ordinary tab switching does not rewrite history.
- The README now matches the app: Java 21, GitHub links, `runDev`, the real
  packaging tasks, how to run the packaged app, menus and keyboard shortcuts.

## Tests
- All 571 headless tests pass, and the production startup smoke test succeeds.
- New coverage includes the splash (image, looping animation, README-consistent
  tagline), adaptive tab widths, the About contact link, compact button density,
  Locations reordering and drop indicators, New Group context menus, Recent
  ordering, Clear-active-tab, remote path validation and SSH connection feedback.

## Upgrade notes
- Users update normally through the built-in updater; there are no database schema
  changes in this release.
- The splash is embedded in the application JAR, so existing VBS shortcuts and
  updated installations use it automatically.
